🛡 UNIOS

Un système d'exploitation universel, construit depuis le secteur de boot — il détecte le matériel, puis orchestre d'autres OS au lieu de les remplacer. A universal operating system, built from the boot sector up — it detects the hardware, then orchestrates other OSes instead of replacing them.

🌍 VisionVision

UNIOS n'est pas un clone d'OS de plus : c'est une tentative de construire une plateforme de boot universelle, capable à terme de démarrer sur un très grand nombre d'architectures (PC anciens et récents, Raspberry Pi, mobiles, x86 et ARM), d'orchestrer d'autres systèmes (Windows, Linux, Android, macOS) plutôt que de les remplacer, de partager des périphériques entre plusieurs machines comme un KVM logiciel distribué, et de servir d'environnement de diagnostic universel, même quand l'OS d'origine ne démarre plus. UNIOS isn't just another OS clone: it's an attempt to build a universal boot platform, eventually able to boot on a huge range of architectures (old and modern PCs, Raspberry Pi, mobiles, x86 and ARM), orchestrate other systems (Windows, Linux, Android, macOS) instead of replacing them, share devices across machines like a distributed software KVM, and act as a universal diagnostic environment, even when the original OS can no longer boot.

🏗️ Architecture en 4 couchesFour-layer architecture

Chaque étage ne charge que le strict nécessaire pour passer la main au suivant — l'ordre est littéralement la séquence d'exécution au démarrage. Each stage loads only what's needed to hand off to the next — the order is literally the boot execution sequence. 

BIOS/UEFI
  └─ Stage 0  (MBR, 0x7C00)    CPUID, charge Stage 1
       └─ Stage 1  (0x7E00)     E820, menu multi-sources, charge Stage 2
            └─ Stage 2  (0x9000)  shell de diagnostic interactif
                 └─ Stage 3  (roadmap)  mode protégé/long, hyperviseur

🚀 Compiler et lancerBuild and run

Prérequis : NASM, Python 3, et QEMU pour tester sans risquer de matériel réel. Prerequisites: NASM, Python 3, and QEMU to test without risking real hardware. 

REM build.bat détecte NASM et Python automatiquement
build.bat
run_x86_64.bat   REM ou run_x86_32.bat
# compilation des trois stages
mkdir -p build
nasm -f bin stage0.asm -o build/stage0.bin -l build/stage0.lst
nasm -f bin stage1.asm -o build/stage1.bin -l build/stage1.lst
nasm -f bin stage2.asm -o build/stage2.bin -l build/stage2.lst
python3 create_image.py

# lancement dans QEMU
qemu-system-x86_64 -drive format=raw,file=build/unios.img
